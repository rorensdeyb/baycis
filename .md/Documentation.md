Phase 2: Progressive Web App (PWA) & Offline Capabilities
To ensure the system remains robust during unstable network conditions around the school premises, a "Progressive Web App" architecture was implemented.
2.1. Service Worker (sw.js)
Pre-Caching: Silently downloads and stores critical UI files (/offline route, style.css, admin.css, admin.js, borrower.js) upon initial load.
Graceful Degradation: Uses a Promise.all().catch() method during the install event to ensure that if one file fails to cache, the entire caching system does not crash.
Fetch Interception: Monitors network requests. If a request fails (user is offline), it safely intercepts the failure and serves the cached offline interface instead.
2.2. Real-Time Network Monitoring
Instant Redirection: Global JavaScript event listeners (window.addEventListener('offline')) are deployed across all pages (Loader, Admin, Borrower). If the connection drops, the user is instantly routed to the offline fallback page.
Smart Return (?returnTo=): The system captures the user's current URL before redirecting to the offline page. Once the connection is restored (window.addEventListener('online')), it automatically routes the user precisely back to where they were.

Phase 5: Backend API & Core Logic Engine
The foundation of the Inventory Management System’s backend was established using Laravel 11, focusing on secure data flow, relational integrity, and automated background processes.

5.1. Eloquent ORM & Database Relationships

Object-Relational Mapping: Configured Laravel Models (User, Item, Transaction, TransactionItem, AuditLog, Notification) to understand the database schema programmatically.
Relationship Definitions: Established complex queries using Eloquent relationships such as hasMany, belongsTo, allowing seamless data retrieval (e.g., automatically finding the specific items attached to a user's transaction).
Security Configurations: Implemented $guarded properties to safely manage Mass Assignment exceptions, ensuring malicious data cannot be forcefully injected into the database.

5.2. RESTful API Architecture

API Initialization: Activated and configured Laravel 11's lean API routing system (php artisan install:api) and verified boot registration in bootstrap/app.php.

Endpoint Creation: Established secure POST routes in routes/api.php to handle the JSON data payloads sent from the frontend user interface.


5.3. The Core Transaction Flow (Borrow → Approve → Return)
Built a robust, multi-step controller (TransactionController) to handle the entire lifecycle of an inventory asset.

Step A: Borrow Request Generation: The system accepts an array of Item IDs, creates a pending transaction, generates a highly secure UUID for the QR code token, and links the items via a pivot table (transaction_items).
Step B: Admin Approval Chain: When an admin approves the request, the backend automatically updates the transaction status, changes the physical items' status to borrowed, securely writes an action record to the audit_logs, and pushes an alert to the notifications table.
Step C: Return Processing: Upon item return, the system updates the transaction to completed with a precise returned_at timestamp, flips the items back to available, and logs the completion audit and notification.

5.4. Database Integrity & API Testing

Foreign Key Constraints: Enforce strict database rules, ensuring transactions can only be processed by verified user IDs and admin IDs currently existing in the system.
Environment Testing: Successfully simulated and verified all API endpoints, validation errors, and JSON success responses locally using Thunder Client before UI integration.

Phase 6: Advanced Authentication & Security Workflows
Following the finalized flowchart, the system's entry protocols were engineered to ensure secure, verifiable access for all school personnel.
Dual-Registration Architecture: Designed a hybrid onboarding system supporting both Admin-initiated account creation (with forced password resets on first login) and self-service registration.
Authentication Engine & Interceptor Pattern: Built custom Laravel Controllers to handle session management and credential validation (supporting both Email and Teacher ID logins). Implemented a strict "Interceptor Pattern" during authentication; if a user requires an OTP or password change, the system immediately revokes their authenticated state (Auth::logout()) and places them in a temporary server-side session holding area. This eliminates security vulnerabilities where users could bypass verification by typing secure URLs directly into the browser.
Atomic Verification (OTP) & Password Loop: Engineered a highly secure verification loop. When an Admin-created user sets their new password, the hashed password is temporarily held in the server session. It is explicitly prevented from saving to the database until the user successfully inputs their 6-digit email OTP. This guarantees atomic transactions and prevents "half-verified" accounts from existing in the system.

To ensure compliance for non-database events (such as database backup/restoration and general system setting adjustments), we implemented manual injection points within the SettingsController and AdminController, creating a hybrid, fail-safe tracking system that captures the full operational lifecycle of the BayCIS platform.
